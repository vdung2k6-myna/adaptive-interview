# Security Guide

> **Backend security details** — For server-side threat model, MCP server security, database security, voice audio storage, and Ollama security, see [`adaptive-interview-api/docs/SECURITY.md`](https://github.com/vdung2k6-myna/adaptive-interview-api/blob/master/docs/SECURITY.md).

This document covers **frontend-specific** security concerns for the Next.js client.

## Frontend Threat Model

1. **HTML / JavaScript injection** — LLM-generated interviewer messages are rendered to HTML
2. **Client-side secret exposure** — Environment variables used in the browser
3. **Service Worker / PWA abuse** — Offline precaching, install flow
4. **Voice interview privacy** — Microphone access and audio playback in the browser

## Mitigations

### 1. HTML Injection (via LLM Output)

**Risk:** Ollama could return `<script>` tags, event handlers, or JavaScript URLs that execute in the user's browser.

**Mitigation:**

- `DOMPurify.sanitize()` strips all scripts, event handlers, and dangerous tags before `dangerouslySetInnerHTML`
- Only the `class` attribute is allowed (for syntax highlighting CSS classes)
- Candidate messages are **never** rendered as HTML — only plain text
- Marked options disable raw HTML input from candidates

**Code:**

```typescript
// MarkdownRenderer.tsx
const html = useMemo(() => {
  const rawHtml = marked.parse(content, { async: false }) as string;
  return DOMPurify.sanitize(rawHtml, {
    ADD_ATTR: ["class"], // only allow class attributes
  });
}, [content]);
```

**Verification:**

- Try typing `<script>alert('xss')</script>` as a candidate — it must render as plain text
- Check that interviewer messages with code blocks do not execute scripts
- Verify `javascript:` URLs in links are removed

### 2. Client-Side Secret Exposure

**Risk:** Putting secrets in a Next.js environment variable that is exposed to the browser.

**Frontend variables used by the browser:**

| Variable | Purpose | Exposed? |
|---|---|---|
| `NEXT_PUBLIC_API_TOKEN` | Injected as `Authorization: Bearer` by `apiFetch()` | Yes (browser) |
| `NEXT_PUBLIC_API_URL` | Backend origin for production builds | Yes (browser) |
| `NEXT_PUBLIC_API_MOCKING` | Enables MSW mock worker | Yes (browser) |

**Non-sensitive variables only.** `DATABASE_URL`, `OLLAMA_BASE_URL`, and backend service credentials must **never** be added to the frontend repository or any `NEXT_PUBLIC_` variable.

**`NEXT_PUBLIC_API_TOKEN` is safe because:**

- It is the same token the browser already sends on every API request
- It does not grant access beyond what the user's browser already has
- It must match the backend `API_AUTH_TOKEN`

### 3. PWA / Service Worker Security

**Risk:** A malicious or stale service worker could intercept requests, cache sensitive data, or serve an old app version.

**Mitigations in `public/sw.js`:**

- Cache name includes a build id generated by `scripts/postbuild.mjs`; old caches are deleted on activation
- Precached shell is limited to static UI assets (`/`, `/offline.html`, `/manifest.json`, `/_next/static/*`)
- API and audio requests use a **network-first** strategy, so sensitive session/evaluation data is not stored in the service worker
- Immutable Next.js chunks are cached by URL hash for long-term caching
- Service worker registration is done from a small inline script in `src/app/layout.tsx`; it is not loaded from a third-party domain

**Verification:**

- Confirm `/offline.html` does not contain session data or PII
- Confirm `/_next/static/*` requests have immutable content hashes
- Verify the service worker scope is the current origin only

### 4. Voice Interview Privacy

**Risk:** Voice interviews require microphone permission and play synthesized audio from the backend.

**Mitigations:**

- Microphone access is requested only when the user enters voice interview mode
- The frontend never stores recorded audio blobs permanently; audio is sent to the backend via `POST /api/voice/stream`
- The frontend only plays audio files served from `/audio/{sessionId}/{filename}`; it does not expose candidate names in filenames
- The Audio Recorder component (`AudioRecorder.tsx`) shows a clear recording indicator and allows the user to cancel

**Browser permissions:**

- `getUserMedia({ audio: true })` is gated by the browser permission prompt
- iOS Web Apps may reset microphone permission between launches — test on a real device

### 5. Input Validation on the Client

The frontend performs lightweight input validation to improve UX, but **all authoritative validation happens in the backend**.

Client-side checks include:

- Required fields before submitting forms
- Maximum character limits on candidate messages (UX only)
- Numeric score ranges in `ScoreInput.tsx` (0–10)

Never rely on client-side validation alone; treat it as a UX optimization.

## Environment Variables

**Allowed in frontend `.env.local`:**

| Variable | Risk | Notes |
|---|---|---|
| `NEXT_PUBLIC_API_TOKEN` | Medium | Must match backend `API_AUTH_TOKEN`; rotate if leaked |
| `NEXT_PUBLIC_API_URL` | Low | Public origin of the backend API |
| `NEXT_PUBLIC_API_MOCKING` | Low | Dev/test flag |

**Must NOT appear in the frontend repository:**

| Variable | Why |
|---|---|
| `DATABASE_URL` | Contains DB credentials |
| `OLLAMA_BASE_URL` / `OLLAMA_MODEL` | Backend concerns |
| `API_AUTH_TOKEN` | Use `NEXT_PUBLIC_API_TOKEN` in frontend only; keep the backend secret in backend `.env` |
| `MCP_AUTH_TOKEN` | Analytics backend secret |
| Any cloud provider key | Backend only |

## Security Checklist (Frontend)

Before deploying to production:

- [ ] `npm audit` passes in the frontend repo (or risks are accepted)
- [ ] `DOMPurify.sanitize()` is applied before every `dangerouslySetInnerHTML`
- [ ] No backend secrets are in `NEXT_PUBLIC_*` variables
- [ ] `.env.local` is in `.gitignore` and not tracked
- [ ] PWA `manifest.json` does not expose internal endpoints
- [ ] `offline.html` contains no PII
- [ ] Service worker does not cache API evaluation/session responses
- [ ] HTTPS is configured for production (required for PWA install)
- [ ] CSP headers are set by the production reverse proxy or backend
- [ ] CORS is configured on the backend to allow only the frontend origin
- [ ] Microphone permission UX is tested on iOS and Android

## Reporting Security Issues

If you discover a security vulnerability, please report it responsibly:

1. Do not open a public issue
2. Contact the maintainers privately
3. Allow time for remediation before disclosure

For backend security concerns, consult [`adaptive-interview-api/docs/SECURITY.md`](https://github.com/vdung2k6-myna/adaptive-interview-api/blob/master/docs/ARCHITECTURE.md).
